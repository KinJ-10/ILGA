# ILGA 10m歩行デモ v0.1

日本語のローカルWebアプリ。対象は **右足の足甲・現在の向き・10m歩行** のみです。
TAGのファームウェアや既存解析器は変更していません。v0.1はexe化していません。

右足・足甲・10mの6試行で、デモアプリの取得→START/FINISH→固定オフライン解析→

v0.1はこの限定範囲で簡易評価合格です。

試行別の根拠と今後の方針は[デモアプリ概要と検出方式 v0.1](../../../docs/GAIT_DEMO_APP_OVERVIEW_V0_1_JA.md)を参照してください。

## Windowsで起動

Python 3.12（pyランチャー付き）、Bluetoothアダプター、現在のBMI270 BLE TAGを使用します。
PowerShellをWindowsの通常フォルダーから開き、次を実行してください。

```powershell
$DemoDir = "\\wsl.localhost\Ubuntu\home\in\work\ILGA\VIEWER\python\gait_demo_app"
py -3.12 -m pip install -r "$DemoDir\requirements.txt"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$DemoDir\start_gait_demo.ps1"
```

標準URLは http://127.0.0.1:8765 です。ランチャーがブラウザを開きます。
UNC上の未署名スクリプトが拒否される環境に対応するため、上のコマンドは
**その起動プロセスにのみ** ExecutionPolicyを指定します。永続設定は変更しません。
既存アプリと競合する場合はランチャー末尾に `-Port 8766` を付けます。
ブラウザを開かない起動は `-NoBrowser`。終了は起動したPowerShellで Ctrl+C。
単体起動は `py -3.12 -X utf8 "$DemoDir\gait_demo_server.py"` です。

## 測定の流れ

1. TAGを右足の足甲へ現在の向きで固定し、他の受信アプリのBLE接続を解除する。
2. 測定名と取得秒数を確認して「取得開始」。標準30秒（10〜120秒指定可）。
   カウントダウンの基準は**最初の正常受信**。探索・接続時間を含まない。
3. 受信開始後に同期用の足踏みを3回し、静止する。
4. 10mの開始線を越えるときにSTART、終了線を越えるときにFINISHを操作者が押す。
5. 終了後3〜5秒静止し、足踏みを3回する。時間満了または「停止して解析」で自動保存・解析。
6. 実測歩数、開始足・終了足、前後の足踏み回数を任意入力して「観察値を保存・結果を更新」。
   受信中と解析完了後に更新可能。未確認は空欄／不明にする。
7. 結果レポートを開く。

足踏み回数は**自己申告**で、自動検出ではありません。未確認または前後各3回未満でも
解析を継続して警告します。この解析は動画時計との同期を必要とせず、PC上のマーカー時計と
受信時計を用います。実測歩数を空欄へ戻すと、実測歩数由来の平均歩幅も算出不可に戻ります。

START/FINISHは各1回・この順序のみ。接続中や受信前には記録できません。
マーカーはWebリクエストをサーバが処理したPC単調時計の時刻です（人の反応・通信遅延を含む）。
FINISH直後に停止するときは、マーカー以降のデータを受信するまで最大0.8秒待ちます。
設定時間の終了が先に来た場合は取得を終了し、区間外マーカーを解析器が警告します。

## 実機受入チェックリスト（継続確認）

操作者が押す時刻を歩行区間とします。右足・足甲・現在の向き、10mの開始／終了線、
TAGの電源、Windows Bluetoothを確認し、他の受信アプリを終了してから実施します。
下記のチェックは**実機で確認したときだけ**付けてください。模擬BLEのテスト成功は代用しません。

- [ ] **1回目を開始**：測定名を「受入01」、取得時間を30秒にする。「取得開始」後に
  接続中→受信中となり、受信件数が増える（TAG検出・BLE接続の合格）。
- [ ] **受信品質**：終了時の実効レートが95〜105Hz（このデモ受入での100Hz相当の目安）、
  欠番0、無効センサー0、受信形式不正0、センサー異常「なし」である。
  最初の数秒はレートが揺れるため終了時に判定する。値が外れたら合格にせず記録する。
  画面の無効センサー／受信形式不正／センサー異常は、それぞれ
  metadataのinvalid_sensor_samples／invalid_payloads／sensor_fault（0=なし）に対応する。
- [ ] **歩行と時刻**：開始前に足踏み3回・静止。開始線でSTART、終了線でFINISHを各1回押す。
  FINISHはSTART後にだけ押せること、markers.csvがSTART→FINISHの2行であることを確認する。
  歩行時間が正の値で、両マーカーのmarker_monotonic_ns差÷1,000,000,000と
  レポートの秒数が表示桁の丸めの範囲で一致すれば合格。
- [ ] **30秒自動終了**：終了後3〜5秒静止して足踏み3回。「停止して解析」は押さず待つ。
  最初の正常受信から約30秒で取得が終わり、解析→結果へ進むこと。
  最終データの受信経過は29.5〜30.5秒を目安とし、解析待ち時間は含めない。
- [ ] **6保存物**：結果レポートのリンクからCSV・マーカー・測定条件・解析JSON・PNGを開く。
  同じ測定フォルダーにsensor.csv／markers.csv／metadata.json／analysis.json／
  waveform.png／report.htmlがあり、CSVに受信行がある、PNGに波形がある、HTMLに結果があること。
- [ ] **実測と参考の区別**：手で数えた歩数と足踏み回数を入力して観察値を保存。
  実測歩数と参考総歩数が別欄に表示され、実測由来の平均歩幅が10m÷入力歩数になること。
  実測を空欄に戻すと実測由来の歩幅は算出不可に戻ること。参考値との不一致は記録する。
  参考総歩数の実測一致はアプリ動作の合格条件ではなく、解析性能の別評価とする。
- [ ] **2回目・再接続**：1回目完了後、同じアプリで測定名を「受入02」にして再び取得開始。
  TAGを再検出・再接続し、同じ手順で30秒取得・6保存物生成まで進むこと。
  保存先が1回目と異なり、1回目のCSV・マーカーが残ること。
- [ ] **エラー時の保持（別の静止試験）**：測定名「受入エラー」で取得し、件数が増えたら、
  歩かず静止した状態でTAGの電源を切る。日本語の通信切断／受信停止エラーが出て、
  取得済み行のあるCSVとマーカー・metadata・計算不可／警告付きJSON・PNG・HTMLが残ること。
  故障したセンサーデータを作るために配線を外す必要はない。

記録欄：実施日時＿＿／操作者＿＿／TAG識別＿＿／1回目フォルダー＿＿／
2回目フォルダー＿＿／エラー試験フォルダー＿＿／各項目の合否・逸脱理由＿＿。
終了時は起動したPowerShellでCtrl+C。現在の状態は「実機受入準備完了・実機未実施」です。

## 結果の意味

- 歩行時間：FINISH−START。速度：10m÷歩行時間。
- 右足由来のstride候補：既存の固定gx検出器が歩行区間内で採用した右足イベント数。
- 参考総歩数：開始足・終了足が分かる場合は既存の2R、2R−1、2R+1換算。
  不明の場合のみデモ表示層で2R概算を示し、警告。基底解析器のJSONは変更しない。
- 平均歩幅：10m÷歩数。**実測歩数由来と参考総歩数由来を別表示**。
- 平均stride長：歩行速度×平均右足stride時間の参考値。区間平均同士の計算。
- cadence：右足stride周期の中央値から換算した参考値。既存の100Hz seq時計が前提。
- ばらつき：全区間CVと既存ルールによる外れ値除外後CVを表示。
- 品質：欠番、受信時刻、測定範囲、候補不足などの既存フラグを日本語化。
  実測歩数と参考総歩数が異なる場合も警告する。
- 波形：6軸、START/FINISH、採用右足候補。横軸はPC受信経過秒。
  既存候補のseq時計を受信時計に対応付けて表示する。

全歩を直接検出しているわけではなく、右足イベントから総歩数を参考換算しています。
検出点は解剖学的な厳密な接地時刻ではありません。個々の歩幅は推定しません。
医療診断、TUG、複数装着プロファイル、足裏など別装着への自動判定は対象外です。
100Hz設定と受信品質、現在の装着向きが前提であり、他の装着条件へ流用しないでください。

## 保存とエラー

結果欄には保存先の絶対パスを表示します。「保存フォルダーを開く」でWindows Explorerを開けます。
この操作はPOST /api/open-folderで現在のrun_idだけを送信し、任意パスは受け取りません。
現在の測定と一致しないID、存在しないフォルダー、アプリ直下runsの外側は拒否します。
WSLの保存先はWindowsから利用できるUNC表記へ変換します。
--output-rootで別の保存先を指定した場合、フォルダーを開く機能は無効です。
レポートは波形→指標の順に表示し、歩行周期・歩行テンポ・測定状態の日本語表記を使います。
解析JSONのフィールド名・状態値・解析式は変更していません。

アプリ直下の `runs/YYYYMMDD_HHMMSS_<種別>_<識別子>/` に保存します。
日時に乱数識別子を加え、既存測定は上書きしません。

- `sensor.csv`：既存受信器と同じ列・単位（mg/mdps）、PC受信時刻付き
- `markers.csv`：既存マーカースキーマ。sourceは互換用operator_key、notesにweb_button
- `metadata.json`：装着、距離、設定秒数、実測値、自己申告足踏み、取得品質、開始／終了時刻
- `analysis.json`：既存解析結果＋表示用demo項目
- `waveform.png`、`report.html`：波形・日本語結果
- `analysis_<識別子>/`：既存解析器のJSON、CSV、候補、区間などの詳細
- `diagnostic.log`：例外時の開発者向け記録
- オフライン時は `source_metadata.json` に元metadataのコピー

通信切断、未受信、マーカー不足、短すぎるデータでも取得済みCSV・マーカーと
計算不可を明示したJSON/PNG/HTMLを保存します。空き容量不足など保存自体の障害は例外で、
画面に日本語エラーを出します。観察値更新では同じ測定のmetadata・表示用結果を更新し、
新たなanalysisディレクトリを作成します。元CSV・マーカーは保持します。

HTML・PNGを閲覧するだけならアプリ起動は不要です。HTMLは同じフォルダーのPNGを参照します。
ブラウザからは当該測定の6種類の成果物のみ公開し、任意ファイルの読み出しは許可しません。
サーバは127.0.0.1限定。Host・Origin・操作トークン、入力範囲、JSONサイズを検証します。
同じ測定に同時操作しないでください。別タブからの古い測定IDは拒否されます。
